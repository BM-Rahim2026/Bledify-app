# Bledify

Marketplace for Algerian home-based makers (women and men, at home or in a small workshop):
traditional cakes, home cooking, couture, crafts, natural beauty, terroir.
Handmade in Algeria only — no electronics or imported goods. Buyers browse
freely; an account is required to order (cash on delivery). Sellers get a shop
link and an order desk to confirm, ship and track. French and Arabic (RTL). Full product brief:
https://claude.ai/artifact/27UBTGXDXnza87jbCa87r8

@AGENTS.md

## Stack
- Next.js 16 (App Router) on Vercel. Seller app is client-rendered (`src/app/seller`),
  public shop `/s/[slug]` is server-rendered for Facebook link previews.
- Supabase: Postgres + Auth (email/password) + Storage (`product-images` bucket).
- All business rules live in SQL: `supabase/migrations/*.sql`. Migrations run
  automatically before `next build` (`scripts/migrate.mjs`), once each.

## Rules to keep
- Statuses: new, confirmed, shipped, delivered, cancelled, returned (legacy
  pending/ready display only). Change status only via `set_order_status` /
  `record_call`; the `orders_before_write` trigger appends `{status, at}` to
  `history` and blocks direct edits to history / no_answer_count.
- Call result only on `new` orders (error P0409). Duplicate public order
  (same shop + phone + items) blocked 10 min (P0409). Rate limits → P0429.
- Risk = phone has 2+ returned/cancelled orders at the same shop (`orders_view.risk`).
- Stats in Africa/Algiers time, weeks start Monday (`seller_stats`).
- Every seller query is scoped by RLS `owner_id = auth.uid()`. Public writes
  only through `/api/orders` → `place_order` (service role); prices come from the DB.
- All UI text through `useI18n().t` / `src/lib/i18n/dict.ts` (fr + ar, same keys).
  Use logical CSS (`ms-`, `ps-`, `text-start`) so Arabic flips. Money via `formatDZD`.
- Wording is gender-neutral (sellers and buyers are women and men). Arabic: no feminine/masculine
  verb forms aimed at the user — use verbal nouns (إضافة، اكتشاف), "يمكن/يجب…", or the shop as subject
  (المتجر). French: "la boutique" rather than "la vendeuse".

## Marketplace
- Categories (fixed list, `src/lib/categories.ts` + SQL check, since 0006): food, fashion,
  crafts, home, terroir ("Produits de la ferme"), occasions, beauty (natural cosmetics, 0009), jewelry ("Bijoux & accessoires", 0013). Subcategories
  (0011): `products.subcategory`, list in `SUBCATEGORIES` (categories.ts) = SQL `subcategories_of()` (test checks),
  labels `sub_<key>` in dict; explore `?category=&sub=` (subcategory dropdown; with a sub,
  results grouped by shop via `public_sellers()` (0014), `&view=products` for the plain grid). Offers (0015): `offers` table run by the team
  (kind seasonal | special, fr/ar titles, image, active) → `/explore?collection=<slug>`. Shops propose products
  (`offer_entries`, always 'pending'); the team approves at `/admin/offers` (admin RPCs `admin_offer_entries`, `admin_review_offer_entry`,
  `admin_offers`, `admin_save_offer`; 0016) or with `review_offer_entry()`. Admins = rows of `public.admins`
  or confirmed accounts whose email is in `public.admin_emails` (0017; SQL only), checked by `is_admin()`
  inside every admin function. `products.tags` =
  approved entries of active offers, written by the database only (shops cannot set it). `products.story` = short maker story.
- Home follows the mockup: ivory/olive/gold, hero carousel, category grid, seasonal offers,
  trust strip, 5-tab bottom nav (`PublicNav`: home, categories, explore, cart, account).
- Cart is local (`src/lib/cart.ts`, one cart per shop, `public_cart` for prices); each shop's
  order is still placed on `/s/[slug]#order`. Favourites: `favorites` table (product xor shop,
  RLS own rows), `src/lib/favorites.ts`, `my_favorites()`, page `/favorites`.
- Trust (0007): `reviews` (one per order+product, only the buyer of a delivered order, via
  `submit_review`; no direct table access; `hidden` = team moderation). `shops.verified` is set by
  the team only (SQL/service role; a trigger ignores seller changes). Delivery by zone:
  `shops.delivery_zones` {local, nord, hauts, sud, grand_sud: {home, desk, days_min, days_max, off}},
  `wilaya_zone()` mirrors `src/lib/delivery.ts` (test checks), `place_order` uses `delivery_quote()`.
- Seller phone/WhatsApp are private (team only, KYC): never returned by public functions or shown
  to buyers; buyers reach shops through Bledify. Phone numbers in shop/product public texts are
  rejected by a trigger (`has_phone`, error `PHONE_IN_TEXT`, 0008).
- Policies (drafts, need a lawyer): `src/lib/legal.ts` (fr + ar, fill OPERATOR), pages `/confiance`
  and `/legal/[doc]`.
- Public browse via SECURITY DEFINER RPCs: `public_home`, `public_products`,
  `public_product`, `get_public_shop`. Customers' orders: `my_orders`.
- `/api/orders` requires a signed-in user and stores `orders.customer_id`.
- Demo content: `0003_demo_seed.sql` (generated by `scripts/build-demo-seed.mjs`),
  sellers `*@demo.bledify.app`, `shops.is_demo = true`, photos on cdn.openart.ai.
  Remove before launch: `delete from auth.users where email like '%@demo.bledify.app';`

## Seller access (0019)
- Everyone registers as a buyer. Selling = applying: creating a shop (the `/seller` onboarding form, also
  reached from "Devenir vendeur" in `/account` or the direct link `/signup?role=seller`) makes
  `shops.status = 'pending'` with `application_note`. The team approves / refuses in `/admin/shops`
  (`admin_update_shop` with `status`, `review_note`). Until approved, `get_public_shop` returns nothing and the
  shop's products stay inactive (trigger `products_moderation`); the applicant can already prepare products.
  A refused applicant who edits `application_note` goes back to 'pending'.

## Admin console (`/admin`, 0016–0018)
- Sections: dashboard, shops (verify, suspend, commission, private contact + payout account), products
  (block / unblock), orders (detail, refunds), payments (refunds due, record payouts), reviews (hide),
  offers (proposals, manage), settings (commission, payout delay, unpaid expiry, admin emails).
- All data through `admin_*` SECURITY DEFINER RPCs that call `require_admin()`; UI helpers in
  `src/components/admin/AdminUI.tsx`. Moderation: `shops.suspended`, `products.blocked` (+ `seller_active` =
  the shop's own choice); trigger `products_moderation` forces `active = false` while blocked/suspended.

## Notifications, warnings, banners (0021)
- `notifications` (no direct access) written by triggers via internal `notify()`: shop decided / suspended, product
  blocked, offer entry decided, payout, new visible order (shop), order confirmed/shipped/delivered/cancelled (buyer),
  report closed, shop warning. Read with `my_notifications`, `my_unread_count`, `mark_notifications_read`; text from
  `kind` + `params` via `ntf_<kind>` dict keys (`src/lib/notifications.ts`). Bell = `NotificationBell`, page `/notifications`.
- `user_settings` (lang, email_digest) via `my_settings` / `save_my_settings`. Daily digest: Vercel Cron (`vercel.json`)
  → `/api/cron/digest` (needs `CRON_SECRET` + `RESEND_API_KEY`), service-role `digest_pending`, `digest_mark_sent`,
  `team_digest` (to-do counts to admins; `todo_counts()` is shared with `admin_counts`).
- Graduated warnings: `shop_warnings` (warning → final → suspension), `admin_warn_shop`, `admin_shop_warnings`,
  shop sees `my_shop_warnings` on `/seller`.
- Home carousel: `home_banners` (public RLS = active and within dates), `/admin/banners` (`admin_banners`,
  `admin_save_banner`, `admin_delete_banner`); without live banners `HERO_SLIDES` are shown.

## Payments (marketplace, 0010)
- Bledify collects every payment (escrow), then pays the shop. Per product: `pay_cod`, `pay_card`,
  `deposit_pct` (online deposit for made-to-order items). `place_order(..., p_payment_method)` computes
  `amount_online_dzd` / `amount_cod_dzd`; online amounts → `payment_status 'pending'`, hidden from the
  shop (RLS) until paid, expired after `platform_settings.unpaid_expiry_minutes`.
- Chargily Pay (`src/lib/server/payments.ts`, env `CHARGILY_SECRET_KEY`, `CHARGILY_MODE`): `/api/orders`
  returns `checkout_url`; webhook `/api/payments/chargily/webhook` (HMAC `signature` header, then re-reads
  the checkout); `/api/payments/checkout` = pay again / sync on return. `PAYMENTS_FAKE=1` = local test page.
- Payment fields are database-only (trigger `orders_payment_guard`). On delivery: commission
  (`platform_settings.commission_pct`, 10 %, or `shops.commission_pct`) on items, credit in `seller_ledger`,
  available after `payout_delay_days` (7). Team (service role / SQL): `record_payout`, `resolve_refund`.
  Shop sees `seller_balance()` at `/seller/earnings`; payout account fields are private.

## Shop logos
- `shops.logo_url` (uploaded image) or `shops.logo` = `{shape, color, content}` (generated badge),
  rendered by `src/components/ShopLogo.tsx`; with neither, a stable default from the shop name.
  Sellers choose in Boutique → Logo (`LogoPicker`). `shop_category()` picks the craft icon.

## AI (sellers)
- Claude via `@anthropic-ai/sdk`, model `claude-opus-5-5`, effort `low`, server-side
  fallbacks on (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`). Shared setup in
  `src/lib/server/ai.ts`; routes `/api/ai/product` (listing from photos, structured output),
  `/api/ai/post` (Facebook/Instagram/WhatsApp post, FR/AR/Darija), `/api/ai/chat` (streamed
  assistant at `/seller/assistant`).
- Needs `ANTHROPIC_API_KEY`; without it the UI shows "assistante non activée".
- Every call spends one credit via `use_ai_credit` (40/day per user, Algeria day).
